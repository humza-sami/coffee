# Genuine schema-v1 migration fixture

This state was generated by Coffee `0.1.0-dev` (API `coffee/v1alpha1`), the original schema-v1 implementation, before schema-v2 input transfer was introduced. It is bundled so source archives and shallow checkouts can test migration without historical Git objects or network access.

All identities, jobs, inputs and the bearer token in this archive are **synthetic public test data. Never use the token or this state for a real deployment.** The state contains one registered Bean, a partially completed job with accepted output metadata and attempt history, and a cancelled job. The accepted result metadata is synthetic; it does not claim a real uploaded artifact.

The legacy executable initialized the state; a driver linked against that same legacy store library submitted, claimed, completed and cancelled work through its API, then recorded `v1-snapshot.json`. SQLite was closed and checkpointed (`user_version = 1`, `integrity_check = ok`); the tar owner names and IDs were normalized. No schema was recreated by hand. No personal paths or production credentials were used. `v1-version.txt` records the executable version; `SHA256SUMS` records the exact bundled payload hashes.

`test_upgrade.py` verifies the hashes before extraction, migrates a copy to schema 2, checks identity/history/configuration/token preservation, executes new work and verifies its output, and restarts the coordinator. Legacy pending tasks fail clearly because schema-v1 did not upload input files. Missing or corrupt fixtures fail the test.

Default: `ctest --test-dir build -R integration_test_upgrade --output-on-failure`.
An alternate complete fixture directory may be selected with `-DCOFFEE_V1_FIXTURE_DIR=/path/to/fixture` at configure time or `COFFEE_V1_FIXTURE_DIR` for direct Python invocation. It must contain the same three payload names and a complete `SHA256SUMS`. `scripts/make-v1-fixture.sh DIR` verifies and copies this bundled fixture; it does not regenerate legacy state.
