# Coffee v0.1.0-alpha.1 (prerelease)

First bounded native MVP. **Alpha: for a trusted owner on machines you control.** Everything was verified as local processes on one
Ubuntu 26.04 host; read [limitations](../limitations.md) before relying on it.

## What is in it

* `coffee` CLI and runtime in C++20: `init`, `validate`, `serve`, `join`, `beans`, `plan`, `brew`, `status`, `logs`, `explain`, `cancel`,
  `drain` (`prepare` is recognised but not implemented and exits 3).
* Coordinator with durable SQLite state, bearer-token authentication (loopback by default), leases/fencing, retries, cancellation,
  restart recovery; Beans that run commands under a supervisor with timeout, address-space limit, CPU pinning, per-attempt scratch cap and
  cleanup after a Bean is killed; digest-verified, content-addressed input/output transfer; dependency outputs between tasks (`from_task`).
* Install to a user-chosen prefix with collision refusal, SHA-256 install manifest and manifest-driven uninstall that never touches state;
  `cpack -G TGZ`; example `systemd --user` unit templates (not installed by Coffee).
* Documentation: README quickstart (executed by a test), [operations](../operations.md) (SSH tunnel / WireGuard / Tailscale recipes),
  [limitations](../limitations.md), [benchmarking](../benchmarking.md), protocol/build references.

## Evidence (all local)

See the [release verification record](../verification/release-verification.md) for commands and scope.

* Release build: unit (all prior unit tests), CLI smoke, protocol, cluster, fault, demo, hardening, quickstart, upgrade and install suites pass.
  A separate ASAN+UBSAN build passes the same suites.
* A bundled genuine schema-v1 synthetic state (created by the pre-network build) opens, upgrades to schema v2 and keeps cluster identity and history.
* A bounded one-versus-two-Bean benchmark on one host with equal CPU budgets and identical verified outputs: see
  [benchmarking](../benchmarking.md) for the numbers *and* what they do not show.

## Not included / not proven

No TLS, no automatic coordinator failover, no pooled RAM or transparent threads, no durable pooled disk, no multi-tenant isolation, no
cgroup quotas; no physical multi-device, WAN, power-loss or disk-full evidence; the CI workflow is configured but has not run on a hosted
runner. The Linux binary is built against glibc 2.43 and needs symbol versions up to `GLIBC_2.38` / `GLIBCXX_3.4.32`; it has not been run on
other distributions.

## Upgrading

Opening a state from the earlier pre-network build upgrades its schema; unfinished jobs from that build cannot run (inputs were never
uploaded) and fail with a clear message.
